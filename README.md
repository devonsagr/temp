# Codex Harness Arena (CHA)

面向 Codex 桌面客户端的个性化 Harness（全局 AGENTS.md、自定义规则、Skills 插件）交付效能评测工作台。

---

## 项目背景

在日常使用 Codex 桌面端编写代码时，开发者常遇到以下实际问题：

1. **配置堆砌与冗余冲突**：随着开发深入，全局 `AGENTS.md` 往往不断追加规则，本地安装的 Skills 插件也可能随时间失效或与新规则产生冲突。
2. **模型过度工程化倾向**：部分前沿大模型在实现简单需求时，容易擅自新增多余的包装层、创建不必要的临时文件或空类，导致上下文与代码库膨胀。
3. **真实交付与无菌跑分脱节**：通用 Benchmark（如 SWE-bench）主要评估无菌环境下的裸模型性能。但在实际工作中，代码产出是由**模型与本地 Harness 组合**共同决定的。

本项目旨在提供一个能够**控制变量**的本地基准工作台，辅助开发者客观衡量：微调后的规则、新增的 Skill 或不同的思考档位，在实际代码交付中究竟是正向收益还是负向干扰。

---

## 前提与边界说明

1. **宿主基准固定在 Codex 桌面端**  
   Codex 桌面端提供了现成的执行环境、沙箱隔离与文件协议。本系统将 Codex 桌面端作为固定的基础底座，主要测试并对比其**外延变量**（包括全局 `AGENTS.md`、局部规则配置、Skills 插件组合以及思考档位）。

2. **理性看待采样随机性与微调波动**  
   大语言模型具备天然的温度采样随机性。在保持基底模型与思考档位不变的前提下，若仅微调几行规则，单次运行存在 **±2~3 分** 的正常波动属合理现象。评测应重点参考**多题目、多次运行后的统计趋势**，而非执着于单次测试的一两分差异。

---

## 评测机制与指标定义

综合评分为百分制（Codex IQ），由机械客观测试与人工工程复审等权结合（50% + 50%）：

$$\text{Codex IQ} = \text{客观自动化得分} \times 50\% + \text{人工工程复审得分} \times 50\%$$

### 1. 客观自动化验证 (50%)
- **测试用例与退出码（50% 机械分）**：自动化单元测试与端到端测试覆盖，进程退出码非 0 视为失败。
- **类型安全与静态检查（25% 机械分）**：TypeScript 编译 0 报错、无隐式 `any`、ESLint 无严重违规。
- **Git 变更纯净度（25% 机械分）**：基于 `git diff --stat` 审查变动范围，识别并惩罚多余的中间层或未授权新建的临时文件。
- **运行时指标遥测**：记录实际耗时、Token 吞吐量、Thinking 推理开销及 Prompt 缓存命中率。

### 2. 人工工程复审量表 (50%)
用于评估自动化用例难以覆盖的代码质量与交付完整度（0 ~ 100 分制）：
- **需求切中度 (30%)**：是否准确理解隐式意图，有无功能减配或过度设计。
- **代码规范度 (25%)**：命名规范、分层清晰度及实现简洁性。
- **边界健壮度 (25%)**：空值保护、异常捕获、竞态与资源管理。
- **交互可用性 (20%)**：界面布局质感、状态反馈与用户体验。
- **合入决策评级**：免修合入 / 微调合入 / 需重构 / 拒绝合入。

## 工作台界面与使用流程

采用左右分栏的 Master-Detail 结构：
- **左侧题库与赛道列表**：涵盖前端交互、核心逻辑、约束遵从、人机协作四大方向，支持“项目构建”与“Bug 修复”分类筛选。
- **右侧沙箱执行控制台**：
  - 查看对应题目的 Spec 契约与标准需求 Prompt（支持一键复制）。
  - 查看绑定的沙箱工作区路径（`~/.codex/sandboxes/eval-...`）。
  - 查看客观自动化验证命令（如 `npx playwright test`）。
  - 执行评测、登记复审结果并查看多维度横向对比。

## 后端接口规范 (面向 Codex 扩展)

当前前端已具备完整的 UI 状态机、模拟采样与本地持久化。关于数据库表结构 (SQLite DDL)、完整 RESTful API 请求响应契约、CLI 驱动代码与沙箱调度的全量技术规范，请直接参考权威文档：

👉 **[完整系统架构与后端实现技术规范 (ARCHITECTURE.md)](./ARCHITECTURE.md)**

核心需补充的 5 个基础接口：
1. `POST /api/benchmark/spawn`：在本地指定目录创建隔离沙箱，并按需注入指定的 `AGENTS.md` 与配置文件。
2. `POST /api/benchmark/exec`：调用本地 `codex exec` 执行任务指令，流式收集日志、退出码与执行耗时。
3. `GET /api/benchmark/diff-facts`：提取 Git 增删行数、改动文件清单，运行编译器与类型检查。
4. `POST /api/judge/review`：组装 Diff 与需求规格，由审查模型生成初步评分参考与行号代码评语。
5. 数据持久化：将现有 `localStorage` 数据平滑迁移至本地 SQLite 数据库。
